通过 Github 自动部署构建 Pages 页面

通过 GitHub Actions 打通「私有源码仓库 → 公开仓库 Pages」的自动部署链路，让代码私有、站点公开，一键发布。

引言

在默认模式下，GitHub Pages 只能读取公开仓库的静态文件，这就意味着如果想用 Pages 做演示，就必须要要包源码一并公开。

为了让源码继续留在私有仓库受保护，同时又能自动把构建产物发布到公开 Pages，我们可以借助 GitHub Actions，即私有仓库负责源码存储与构建 -> Actions 自动 push 产物到公开仓库 -> 公开仓库仅仅做 Pages 托管。这样既能保持源代码私有化，又能享受 GitHub 免费的静态站点服务，实现源码与部署完全分离。

下面按顺序给出 5 步可落地操作，15 分钟即可跑通整条链路。

步骤1：准备两个仓库

GitHub 右上方菜单 -> Create new… -> New repository，创建一个私有仓库和一个公开仓库。

步骤2：创建 Personal access tokens (classic)

GitHub 右上角头像 -> Settings -> Developer settings -> Personal access tokens -> Tokens (classic) -> Generate new token -> Generate new token (classic)，创建一个 personal access token (classic)。

注意：这个 Token 生成后，只在第一次可见，之后就不可见了，一定要要保存好。格式：ghp_xxxx。

步骤3：将申请的 Token 存入到私有仓库的 Secrets 中

进入私有仓库 -> Settings -> Secrets and variables → Actions → New repository secret，Name 填 PUBLIC_REPO_TOKEN，Value 贴刚才的申请的 Token 值。

注意：Name 可自定义，但需要和下面 Actions 的 personal_token 这个名称保持一致。

步骤5：公开仓库开启 GitHub Pages

公开仓库 -> Code 创建 gh-pages 分支 -> Settings -> Pages -> 设置访问页面分支。

注意：可在 Custom domain 自定义域名，自定义时别忘记添加域名解析 CNAME 记录。

步骤6：搭建完成，流程启动

流程执行过程：

  1. 本地调整代码 -> push 到私有仓库。
  2. 私有仓库 Actions 自动构建 -> 把静态文件推送到公开仓库。
  3. GitHub Pages 自动更新，线上立即生效。

全程保证源码始终在私有仓库中存储，公开仓库只有编译后的文件，无历史记录，达到“源码私有 + 站点公开”的目的。

常见问题

1. 权限报错 403

检查 Token 是否对 public_repo 有读写权限。仓库路径是否有错误。

2. Pages 404

确认公开仓库是否开启 Pages，选择的分支与私有仓库 workflow 推送的是否一致；产物目录是否包含 index.html。

3. 保留历史 commit

将 force_orphan:ture 改为 force_orphan:false，公开仓库会带 commit 记录。

4. 慢构建/内存溢出

加 NODE_OPTIONS: --max-old-space-size=8，或换 runs-on: ubuntu-latest-4-cores

注意：runs-on: ubuntu-latest-4-cores 属于 GitHub 的付费功能，仅在 Team 或 Enterprise 云计划中可用。免费用户只能使用 runs-on: ubuntu-latest（2 核 7 GB）。
